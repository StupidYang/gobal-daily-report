# GDR · 市场与全球情报

**先看结论与影响，再按兴趣展开全部资料。**

这是定时研究快照的阅读终端，不是实时交易软件。当前界面为 **reader-r2**，数据仍兼容 **schemaVersion=5**。保留当前完整分析、滚动24小时演化、最近新增，以及原有全部资产、宏观和证据内容。

## 首屏与资料库

PC首屏只承担简报职责：白话结论、主要影响、最近三项重要变化、下一节点、最多六组核心指标。正文默认15px，可切换大字；白色/浅灰为主，蓝色与淡色点缀，支持可选深色。

后面的主题库默认折叠，内容没有删减：

- 白话影响与综合结论：对谁偏利好/利空/分化、为什么、多久、什么会改判。
- 中国/美国/全球新闻：独立增加综合时事，地区筛选、搜索和继续展开不裁掉数据。
- 24小时变化与曲线：最近新增、窗口累计、全过程、真实观测和排除原因。
- 多框架与判断账本：框架本轮结论、共识/冲突/权衡，以及原有事实、解释、反证和修订。
- 完整详报：所有资产、宏观实际/预期/前值/修订、原财经新闻、触发器、情景和定义。
- 事件雷达与证据：所有来源、canonicalFacts、数据状态和市场覆盖。

内容总量增加不靠挤压财经深度，也不靠新闻硬凑数。新闻条数是不同事件数，跨地区标签计数可以重叠。没有直接市场影响的社会大事也可保留。

## 新的数据内容

新任务读取两份契约，写 `reportMeta.contractVersion="reader-r2"`，新增：

- plainLanguage：白话综合结论和逐资产影响。
- frameworkAnalysis / frameworkSynthesis：有真实输入、适用边界和反证的多框架判断。
- newsroom：滚动24小时的中国、美国和全球综合时事，含事实、影响、自己的判断、来源与时点。

原有fields不删除；节点通知可以短，latest的JSON仍完整。具体格式与最低要求见契约。

09:35的手工补注仅解释该版本保存的旧证据，没有重新采集市场新闻。浏览器核对报告ID与Git blob SHA，只有与指定原快照一致且没有新白话字段时才载入；原latest和历史数字均未改写。SHA不符或不可验证时安全跳过补注。

## 曲线为什么可能只有点或没有曲线

曲线不是靠等一次定时任务自动出现，而是靠真实、可比的观测：数值、seriesKey、valueType、unit、scope、contract和数据asOf。至少两个不同数据时点才可连线，超过六小时空档断开。

- null/文字阈值不转成精确数值；日期模糊不当整点。
- 指数点位与涨幅%分开，收益率和bp分开，期货月份分开，ETF流量不是价格。
- 重复收盘报价按实际时点去重，不在每份报告时间重新造点。
- 跨资产对照需要共同的实际数据基线；可选择符合条件的资产子集。
- 面板提供样本排除原因和可查看的实际观测记录。稀疏快照不能证明领先关系或因果。

## 阅读保护

同一报告不重绘；后台发现新版本先提示，等用户载入。检查失败保留当前内容，历史查看不会被自动拉回最新。手动检查与历史切换发生竞争时，较新的阅读意图优先。

大字、主题和已读标记在可用时保存到localStorage；浏览器禁用存储仍能阅读。“标记已读”由用户点击，后台检查不会替用户标记。证据链接自动打开父级折叠区。

## 三个任务与发布

每四小时主干、亚洲开收盘、美股开收盘保持既有调度；此次界面升级不改时区、频率或创建新任务。它们共同读取基础契约与reader-r2补充契约，只更新latest、history与history-index，禁止修改前端和手工补注。

写前重新获取SHA、旧时点不能覆盖新报告；历史先写，再latest，再索引重新合并；写后校验。该协议是应执行的乐观并发流程，不是数据库事务或外部服务永不失败的保证。

## 开发与检查

```bash
python3 -m http.server 8000
node --test tests/*.test.cjs
node scripts/validate-report.cjs data/latest.json
```

GitHub Reader checks会运行语法、回归与报告结构检查。旧报告采用兼容校验，不要求回填新字段；标明reader-r2的新报告执行更完整的内容和引用检查。少于新闻目标只作覆盖提醒，不鼓励为了过检查造新闻。

这些检查不验证新闻真实性，也不是Pages发布的事务门禁。浏览器布局回归在离线Chromium中用实际字段节选和明确标识的测试夹具完成，覆盖320/390/768/1440、默认折叠/全部展开、大字、历史切换、请求失败和恢复、无存储、新闻筛选和全量展开。不是手机真机或公开Pages域名的端到端验收。

## 部署

GitHub Pages从main根目录发布。先提交assets/数据契约等依赖，再切换index入口。仓库提交、CI结果、Pages部署和用户浏览器显示分别核对，不把其中一个成功冒充全部成功。
