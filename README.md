# GDR · 个人市场情报台

**看清现在、恢复变化、检验判断。**

页面是定时研究快照的阅读终端，不是实时交易软件。当前采用 **schemaVersion=5**，保留当前完整分析、滚动24小时演化和最近新增三个层次。

## 阅读方式

- 总览：当前主线、最多六组核心指标、下一关键事件。
- 变化：最近新增与窗口累计分开，展开可读演化过程。
- 判断：事实、解释、替代解释与验证条件；修订账本显示本报告收录主题的状态。
- 详报：按资产展开全文，查看数据质量、事实范围与来源。

每个视觉元素都有用途。A股指数合成风格组，避免四张重复卡占满首屏；ETF披露不是价格走势；数据状态只做真实计数，不计算“健康评分”或“预测胜率”。

## 文件结构

```text
index.html                    静态页面入口
assets/terminal.css           字体、布局与响应式阅读样式
assets/terminal-core.js        时间、指标身份、序列、统计与引用检查
assets/terminal.js             渲染、历史切换、阅读状态与图表
 data/latest.json             当前完整报告
 data/history-index.json      历史目录
history/YYYY-MM-DD/HHmm.json   已发布报告快照
docs/report-contract.md       三类自动任务共享的数据与发布契约
tests/terminal.test.cjs        纯逻辑回归测试
.nojekyll                     GitHub Pages静态发布标识
```

没有前端框架、外部字体、CDN图表依赖、遥测或浏览器端密钥。自动任务只生产数据；不得更改入口、样式和脚本。

## 图表的可信边界

图表只画保存过的真实数值观测，不把报告时间当行情时间。`rawValue=null`、文字阈值报价、时间不明和不兼容数据不会被补成曲线。

同一序列必须有相容的 `seriesKey / valueType / unit / contract / asOf`。指数点位不能接上日涨幅；不同月份期货不能直接拼接；重复收盘快照按实际数据时点去重；超过六小时的观测空档断线。

跨资产比较仅在存在共同实际数据时点、且每条序列至少两条有效观测时归一化。无共同基线显示数据不足，不分别选不同起点制造联动。稀疏快照不能证明领先关系或因果。

旧v2/v3/v4报告仍可阅读。历史缺少图表元数据时正常降级，不为美观改写过去；未来任务采集到足够可比观测后才逐步出现更多图形。

## 阅读交互

正文默认15px，可切换大字。主要布局针对桌面、平板与窄屏手机。

“检查新报告”只读取已经发布的JSON，不触发市场研究。未变化不重建DOM；自动发现新报告先提示，不打断阅读；查看历史时不被拉回最新；读取失败保留当前内容；恢复成功清除错误状态。

“标记本版已读”由用户明确触发。浏览器不允许localStorage时，仍可正常阅读。事件时间待定不会被午夜占位时间冒充确定倒计时。

## 数据与任务

三个任务保持原分工：每四小时完整主干、亚洲开收盘补充、美股开收盘补充。任务需先读取 **docs/report-contract.md**。本文不改变调度时区或频次。

关键事实统一存放在 `canonicalFacts`。资产卡、判断和详报通过factId引用。必须区分发布时间、数据截止时间与真实核验时间。ETF部分披露不能写“至少净流入”；总清算、空头清算、多头清算及BTC/全市场OI必须区分。

节点的推送可以短，但写入latest的内容仍须完整。写入采用历史先保存、latest再更新、索引合并去重及写后核对；旧任务不得覆盖更新报告。该协议不是数据库事务，不应宣称外部服务永不失败。

## 本地使用与回归

```bash
python3 -m http.server 8000
node --test tests/terminal.test.cjs
```

HTTP服务在仓库根目录启动后访问首页。Node测试覆盖时间解析、缺失状态、统计总数、合约分离、指数点位与涨幅混用、历史去重、跨资产共同基线与引用检查，不校验金融消息的真实性。

本次实现还在离线Chromium中以仓库实际字段节选做了320、390、768、1440宽度和交互测试，检查横向溢出、大字、历史切换、展开状态与失败恢复。这不等于iPhone/Android真机或公开Pages域名的端到端验收。

## 部署

GitHub Pages使用main分支根目录。先提交assets，再切换index入口，避免入口引用尚未存在的资源。仓库提交成功、Pages部署成功、用户端可视化验收是三个不同阶段。
