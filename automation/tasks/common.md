# 原生任务入口约束（execution-lease-v1）

本文件替代旧的原生任务直接拼写七模块并提交main的流程。角色文件只规定内容责任，不决定写入路径。

首先读取main生产控制文件，暂停或不可读就退出。详情严格按 `docs/live-execution.md` 执行。生产允许时，先读取gdr-runtime的共享锁与最近outcomes；明显有未终结执行就直接报告busy，避免先做一轮昂贵搜索再被锁拒绝。随后进行**请求前证据发现**：联网查找本轮真正需要阅读的新闻、官方发布和研究原文，选择具体文章/公告/数据页URL，而不是把网站首页、栏目页或搜索结果摘要当成已研究材料。除非栏目页本身就是官方最新发布清单，否则不能用首页占掉证据槽。

每个documents条目应带稳定id、url、title，并尽量标kind=news/macro/research/official/general；单轮最多32条。小时增量优先“新事件/新进展/旧判断失效证据”，滚动24小时仍有效的合格新闻由代码保留，不要求每小时重新抓满18–30条；深度复核或长暂停后的首轮可以提高证据数量，但不得凑数。发现不足就把缺口写进source plan和最终coverage，不用旧闻冒充新闻。

完成来源计划后，原生任务仅在gdr-runtime分支提交一个请求、读取代码采集结果、完成绑定真实来源包的分析后提交一个editorial。代码负责共享锁、截止时间、并发抓取、JSON组装、质量校验与唯一发布。

禁止创建子任务、直接写main、修改锁、伪造回执、绕过暂停开关。固定期限过后停止，旧任务结果不再提交。来源缺失不补0，不将旧价格换时间，不用期货冒充现货或用日度收益率冒充盘中。

小时轮次只减少重复研究，不能删除完整六资产详报。每四小时的深度复核属于同一个主任务。研究保留原分析时间与来源；增量观察单列。财报研报未读全文不可声称全文研究。行业名单和个股样本不等于全市场排名。

成功需要main批次回执、冻结历史及公网版本核验，运行中的任务、提交的请求、采集完毕和配置已启用均不是发布成功。验收期间三个任务保持暂停，不修改调度频率或数量。

### 交接修订补充（优先于旧单模块分工描述）

读取docs/editorial-input.md。本区域交易节点也需要把本轮quotes和news一起交给代码发布，不得为沿用旧模块丢弃刚采到的报价。code编译器负责保留仍有效的历史新闻并隔离旧格式，不要求模型猜测补齐历史缺项。收到needs-revision，在同一截止时间内仅创建一次`--r1.json`修订。failed/超时后立即结束，不开启任何定时副本。
