# GDR 每小时全球主报告

任务标识：global-main

每小时整点启动一次，统一以 Asia/Singapore（UTC+8）判断报告窗口。启动时间不是保证发布完成时间。仍只有一个主任务，不为小时快报或深度报告创建额外任务。

必须先读 automation/tasks/common.md。内部角色：quotes, asia-equities, us-equities, news, macro, research, synthesis。按 automation/prompts/<role>.md 的内容职责执行；提交方式一律使用 atomic-batch-v2 整批协议，仍须一次提交七个模块和完整综合报告。

## 同一任务内区分快速更新和深度复核

- 每小时：核对最新可得行情、市场交易状态、新闻增量及已发布事件，说明相比上一版发生了什么、证据是否改变原判断、下一步观察什么。更新当前有交易的市场；休市市场保留最后有效快照及其真实时间，除非有新披露或重大事件需要更新。
- UTC+8 的 00、04、08、12、16、20 点：同一轮升级为深度复核，重审跨资产逻辑、风险、情景及完整24小时演化，不再额外生成一次任务或重复报告。任务延迟时，以实际当前小时判断模式，不伪造原计划时刻的行情；必要时说明深度复核错过窗口。
- 其他小时默认增量分析。研究仅处理新增材料或使旧判断失效的新证据，不每小时重读同一财报。重大事件出现时可在本轮加深分析，不另建事件调度任务。
- 轻量指减少重复采集和推理，不是删掉报告内容。每轮产物仍是可独立阅读的完整报告，明确标注本轮新增、重新核验、沿用、缺失；A–G、资产详报、全部合格新闻及证据保留。

## 复用与发布约束

复用原始资料必须保留 asOf、verifiedAt、analyzedAt 等真实时间，不得把新报告时间当成旧资料更新。需要将复用输入纳入本批次时，以新的模块 runId 封装并注明复用来源；不得覆盖或修改已有不可变 run。新封装的 generatedAt 只表示封装生成，不证明内容重新采集或核验。

本轮冻结上一版与最新模块后，提交前再次检查候选、回执和正式指针。同一小时已有 global-main 的 pending 或 published 候选时，不再重复提交。发现更早主任务的候选仍未终结，先核对状态并如实跳过，禁止无限补跑。区域任务已取得的同一来源、同一真实时点数据应复用，不再重复抓取。

没有可验证新数据或实质变化时，说明“本小时无实质变化”，不为凑数编事件或改写相同观点。若发布完整快照，必须保留来源原时间，且每轮最多提交一个整批候选；不重复触发构建。

## 恢复前验收

productionPaused 与平台暂停状态保持不变。除了已有准入条件，小时频率需要验证跨小时重复触发、采集未完成就进入下一轮、与区域节点同时发布、过期数据复用及预算不足降级。候选目录检查不能证明尚未提交的采集过程互斥；必须通过真实试跑确认或补齐执行级防重入机制。配置更新或测试数据通过都不能代替这些验收，也不能自动恢复生产。


## 当前执行协议（替代上文旧提交方式）

以 docs/live-execution.md 为准：原生任务只在gdr-runtime新建请求与editorial，代码组装并发布。先检查runtime/outcomes忙碌和失败回执，不空等；共享锁与代数先于采集，固定截止前提交，不能直接手工写main批次。此前的频率、内容深度和诚实来源规则继续保留。
