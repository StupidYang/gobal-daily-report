# GDR 系统续修：执行拆分、交付次序与验收边界

## 结论与范围

目标是持续产出可用情报，不是持续产生绿色工作流。保留现有项目、三条原生调度、共享执行锁、单一原子发布出口、content-r3 和 reader-r2。本文不授权开启生产，不创建验收或补跑调度，不修改旧报告。

本轮基于 `dfbea023c405611bb610cd7bac73a29f656dee89`，源码树 `9ece1e8ee514859082d6276fd245931af444ac44`。源码来自已有 CI 35944720379 的 source.zip，本地重建 Git tree 与该 main 提交完全一致。其后自动构建的生成文件与本轮修复分开记录。

## 一、已经复现并隔离修复的问题

| 问题 | 可复现原因 | 本轮改动 |
|---|---|---|
| 文档被行情饿死 | 原程序先跑完全部行情，再在同一个90秒预算内开始文档 | 五类工作项轮转，所有工作项仍共享一个最多4并发的生产池；不增加超时、不加重试 |
| 宏观旧材料无限续期 | 每小时包装产生新 generatedAt，下一轮又按这个新时点判断24小时 | 用最初 retention.generatedAt 固定保留期限，保持原 runId/dataAsOf，不让新包装延长证据寿命 |
| 沿用说明持续膨胀 | 每轮把上轮完整说明再追加同一句原因 | 原因去重，保留同一个原始沿用身份 |
| 外部覆盖假完整 | 一个地区的外部文章可借另外地区的价格观察凑 CN/US/WORLD | 外部事件地域独立计数；行情观察不能补外部覆盖；完整声明还需实际非财经事件 |

`lib/collection-plan.cjs` 产生的是同一 execution 的工作项，不是原生模型子任务，也不是额外调度。新闻/宏观/研究目前分开的是取证队列；本文不声称已实现多个并行模型或自动完成研究。

## 二、整体执行结构

```text
现有 global-main / asia-session / us-session
  -> 读取暂停开关、检查已有执行
  -> 来源发现与范围计划（只读检查不能代替CAS）
  -> 共享 execution lease / 原20分钟准入期限
  -> 单个有界采集池，按工作类别轮转
       required-quotes  : 必看31项
       news-documents   : 新闻/综合时事原文
       macro-documents  : 宏观和资金原始材料
       candidate-quotes : 41家配置候选基础报价
       research-documents: 新事件触发公司材料
  -> 不可变来源包、每类成功/失败数、packetHash
  -> 完整分析或显式沿用（不把未获取说成无变化）
  -> 六资产正文、来源引用、时间口径和领域覆盖检查
  -> 一个整批候选、一个发布者
  -> 仓库回执 -> 公网字节与浏览器证明
```

共享并发仍是生产配置4，而不是每类4加起来20；单请求8秒、采集90秒、既有执行期限和修订次数不变。任何预算下仍可能失败，轮转只保证不同类别能尽早得到执行机会，不承诺慢源也能全部取齐。限流、来源时点、合约、币种和内容门槛不放松。

## 三、交付顺序与完成条件

### A. 先做有边界的单轮

本轮完成上述四项反例回归。补充只读 `node scripts/audit-coverage.cjs`，从最新报告冻结的模块读取覆盖，不用当前模块指针污染旧报告。审计脚本不抓取、不写文件、不发报告、不批准恢复。工程测试通过只是准入，不是事实及推理审核。

后续仍需处理：新来源是否确实属于本轮来源包；部分宏观更新是否保留未受影响的旧项；未读正文不能被HTTP200包装成研究完成；错误与确认无新材料须有不同状态。这些不能靠更多调度解决。

### B. 内容生产能力逐项接通

| 内容 | 实施边界 | 合格产物，而非口号 |
|---|---|---|
| 综合新闻 | 发现、事件去重、具体原文、时间精度、影响/解释分别处理；增量复用滚动窗口 | CN/US/WORLD 和非财经实际事件的来源链；不知道时间或未读原文的记录不能伪装本轮已核验；18–30条继续是目标而非凑数配额 |
| 宏观与资金 | 报价、宏观发布、ETF、OI、费率、清算是不同适配器；无授权或接口就显式未接入 | 每项有资产/场所/统计窗口/单位/披露完整性；部分基金披露不冒充全市场总额 |
| A/H行业排名 | 接通真实成员集合与版本，再接同交易时长量价基线；当前空group构造器需要真实输入通路 | observed/expected/eligible/scorable 与排除原因；样本榜不能叫全行业榜；缺量比不能用涨幅代替 |
| 公司研究 | 批量查材料身份，按事件键缓存；最多新分析5家不是最多检查5家 | 41家候选检查结果、待研究新事件队列、原研究时间、原文范围与证伪条件；没有检查不能说无新披露 |
| 综合判断 | 六资产独立详报与A–G/框架保留，增量更新只动有证据变化的部分 | 每版可独立阅读，沿用保留原 analyzedAt，并附本轮复核/变化/失效记录 |

不能等所有领域都做完才第一次验证单轮，也不能把部分领域上线包装成整套产品合格。缺口应在领域状态中可见，不以清空旧内容或放松门槛换取发布。

### C. 明确授权后才进行原生连续验收

先使用现有全球任务观察至少三轮，其中含一轮深度复核；这只是冒烟验证。随后按自然调度观察至少24个小时槽，记录完整、失败、busy、超时和未观测槽，不把busy计成功，不把补发报告算按时产出。更长稳定性仍需后续观察，24小时不是永久保证。

每轮按同一executionId核对：实际触发、锁代数、取证、分析、修订、候选、仓库、部署、内容覆盖。不能拿采集几秒钟代替模型研究加部署的端到端耗时。代码重新部署同一份旧报告不算新轮次。

全球任务的证据成立后，再分别验证亚洲节点与美股节点的共享锁竞争、交易时区、节假日和早收盘。授权恢复的范围另行确认；本轮不修改任何调度。

## 四、是否增加原生任务

本轮选择先拆执行工作而不增加调度。只有实测发现模型研究成为无法通过缓存、预算和分段契约解决的瓶颈，再提出分开“证据生产”和“综合发布”的调度方案。新增的入口、权限、费用与重复执行风险必须重新说明并取得授权。不能把用户愿意讨论拆分当成恢复或新增定时任务的许可。
